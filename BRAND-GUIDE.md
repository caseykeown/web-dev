# Custom Web Architecture — Brand Guide

This document records the brand and design decisions behind the site rebuild. Update it when the brand changes; don't let the site drift from it.

## Brand personality

Approachable, dependable, skilled, practical, personal, kind. The test for any new copy or design decision: *does this feel like a capable, trustworthy neighbor who happens to be very good at building websites?*

**Positioning statement:** Custom Web Architecture builds straightforward, professional websites for small businesses that want personal service, honest guidance, and a site they can be proud to share.

**Primary tagline:** Websites built with care and common sense.
**Supporting line:** Websites built by Casey Keown.

## Logo usage

Three approved marks live in `/assets/`:

- `cwa-horizontal-black.png` — primary lockup (monogram + wordmark). Use in the site header and anywhere the full name should appear.
- `cwa-monogram-transparent-black.png` / `cwa-monogram-transparent-white.png` — the standalone monogram. Use for compact spaces (social avatars, favicons-adjacent contexts) where the full wordmark won't fit.
- `favicon.svg`, `favicon.ico`, `favicon-96x96.png`, `apple-touch-icon.png`, `web-app-manifest-192x192.png`, `web-app-manifest-512x512.png`, `site.webmanifest` — the full favicon/PWA icon set, already wired into every page's `<head>`.

Do not reintroduce the "Casey's Space" wordmark, the CK personal monogram, or `operator.png` (tactical AI-generated image — do not use anywhere on the site).

`drummer.png` may still appear sparingly as a personal illustration (e.g., a small detail on the About page) but is not a business mark.

## Color tokens

Defined as CSS custom properties in `css/styles.css`:

| Token | Hex | Use |
|---|---|---|
| `--color-orange` | `#F47A3C` | Buttons, links, highlights, primary CTAs |
| `--color-orange-dark` | `#D6602A` | Hover states, link color |
| `--color-charcoal` | `#242424` | Body text, footer background |
| `--color-cream` | `#F6F1E8` | Page background |
| `--color-cream-soft` | `#FBF8F3` | Header background, subtle surfaces |
| `--color-green` | `#64745A` | Secondary accents, metadata |
| `--color-gray` | `#D9D6D0` | Borders, dividers, card backgrounds |

White and black are used only where there's a clear functional reason (e.g., footer text on charcoal). All text/background pairings meet WCAG AA contrast.

## Typography

- **Headings:** Archivo (600/700/800)
- **Body:** Inter (400/500/600/700)

Loaded via Google Fonts with `preconnect` and `font-display: swap`. Type scale uses `clamp()`-based custom properties (`--step--1` through `--step-4`) so headings resize smoothly across viewport widths instead of jumping at breakpoints.

## Voice and language rules

Write in first person, as Casey. Avoid agency language ("we deploy," "our team leverages," "cutting-edge," "elevate your brand"). Prefer specific, plain-English explanations over slogans. Assume the reader doesn't know what a domain, host, or CMS is, and explain accordingly.

## Approved calls to action

Use these three consistently, exact wording:

- **Request a Quote** — always links to `/leads.html`
- **Book a Consultation**
- **View My Work** — links to `/work.html`

## Image style

Real screenshots of completed projects, real photography of Casey (`/assets/headshot.jpg`, an optimized version of `white-background-headshot.png`), and simple branded graphics. No stock photography where a real asset will do. No invented testimonials, statistics, certifications, or client claims.

## Prohibited visual treatments

No camouflage, crosshairs, military graphics, tactical language, neon-green binary/Matrix effects, metallic gradients, heavy black-on-black styling, MySpace-era visual conventions (profile "Top 8," comment walls, browser chrome jokes), or police/law-enforcement imagery (uniforms, badges, patches, vehicles, rank).

## Components

Reusable classes are defined once in `css/styles.css` and shared by every page and every blog post generated by `scripts/build_blog.py`:

- `.btn`, `.btn-primary`, `.btn-secondary`, `.btn-quiet` — buttons
- `.card`, `.card-grid` — general content cards
- `.project-card`, `.project-thumb` — portfolio cards
- `.process-list` — numbered process steps
- `.cta-band` — orange call-to-action band
- `.field`, `.field-row`, `.radio-row` — form controls
- `.site-header`, `.site-footer` — shared header/footer, identical across static pages and blog pages

## The blog pipeline

`scripts/build_blog.py` regenerates `/blog/index.html`, every `/blog/articles/<slug>/index.html`, `/blog/feed.xml`, `/sitemap.xml`, and the "Latest articles" card grid on the homepage every time a markdown file is pushed to `/blog`. Its `shared_header()` and `footer()` functions contain the actual HTML template — if the brand changes again, update those functions, not just the static pages, or the next blog post will regenerate pages with stale branding.
